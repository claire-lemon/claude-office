# 설계: 회의 내용을 칠판에 자동 반영

- 작성일: 2026-09-29
- 상태: 설계 (구현 중)
- 요청: "회의의 내용이 todo로 자동 추가되어야 함"

## 1. 사실

| 항목 | 사실 | 근거 |
|---|---|---|
| 오늘 실제 회의 3번 | 세 번 모두 사용자 발언 0번. 진행자가 제안을 올리면 읽고 바로 "회의 끝" | 진행자 대화 기록(`#meeting-2026-09-29-1~3`) |
| 칠판에 남은 할 일 | 0개(세 번 모두 `## 회의 n` "오늘 할 일 확정 0개") | 오늘 일지 |
| 원인 | 지침 v2가 "사용자가 고르거나 고친 항목만 확정 → CLI로 기록"이라, 대답이 없으면 아무것도 적지 않는다 | `src/domain/meeting.mjs` 지침 §순서 3·4 |
| 진행자의 도구 사용 | Read(지침·일지)와 한 번의 `ls`뿐, CLI 실행 0번 | 대화 기록 |
| 일지의 세션 줄 | 제목·상태·변경·📋만 있고 프로젝트 폴더가 없다. 진행자가 할 일의 폴더를 고를 근거가 약하다 | `src/domain/daily-note.mjs:55` |

## 2. 설계

1. **진행자의 제안 = 오늘 할 일.** 진행자는 매 답변 끝에 `### 칠판` 목록을 정해진 형식으로 쓴다. 서버가 그 목록을 칠판에 반영한다. 사용자가 대답하지 않아도 첫 답변만으로 칠판이 채워진다.
   ```markdown
   ### 칠판
   1. 결제 모듈 리팩터링 — api-server
      1. PG 응답 파싱을 use-case로 옮기기
   2. 클라우드 문서 커밋·PR — knowledge
   ```
   1. 한 줄 = `N. <제목> — <폴더 이름>`. 폴더 이름은 일지 `## 최근 프로젝트 폴더`의 이름(또는 절대 경로) 그대로
   2. 하위 항목(3칸 들여쓰기)은 세부 메모(`detail`)
   3. 오늘 실제로 할 일만, 우선순위 순, 최대 7개
2. **동기화 (`syncMeetingBoard`, 서버)**: 오늘의 열린 진행자(아카이브 안 된 최신) 마지막 답변에서 마지막 `### 칠판` 목록을 읽어 계획을 세우고 적용한다. 같은 답변은 다시 처리하지 않는다(답변 해시를 메모리에 기억).
   1. 목록에 있고 칠판에 없음 → 생성(`source: 'scrum'`, `meeting: { id, key }`. key = 정규화한 처음 제목)
   2. 이 회의가 만든 항목 → 세부·폴더가 바뀌었으면 수정(제목은 사용자가 고쳤을 수 있으니 건드리지 않음)
   3. 같은 제목(정규화: 공백 정리·소문자)의 할 일이 이미 칠판에 있음(수동·이전 회의) → 건너뜀(중복 방지)
   4. 이 회의가 만든 항목인데 목록에서 빠짐 → **시작 전(`open`)이고 사람이 손대지 않았으면**(수동 체크·배정 없음) 소프트 삭제. 시작했거나 손댄 항목은 남긴다
   5. 폴더 이름을 못 찾거나 같은 이름이 둘 이상 → 만들지 않고 `skipped`로 보고
3. **언제 도는가**: 서버 안 타이머 3초마다 + "회의 끝"을 누를 때 아카이브 직전 한 번. 진행자가 없거나 끝났으면 아무것도 안 함
4. **지침 v3**: CLI를 쓰지 않는다(파일 쓰기·명령 실행 없음, Bash 권한 확인 문제도 사라짐). 순서는 ① 지침·일지 읽기 → ② 첫 답변: 어제 끝낸 일 / 못 끝낸 일 / 오늘 추천 + `### 칠판` → ③ 사용자가 말하면 조정하고 매번 `### 칠판`을 새로 씀 → ④ 사용자가 조용하면 그대로 둠(칠판은 이미 반영됨). 칠판 형식과 규칙(폴더 이름 목록, 7개 이하, 중복 금지)을 명시
5. **일지 세션 줄에 폴더**: `… · 📁 <폴더 이름>`(자동 구간). 진행자가 할 일의 폴더를 고르는 근거
6. **회의실 화면**: 진행자 탭 상태 줄에 "칠판에 반영: N개"와 건너뛴 항목("폴더를 몰라 못 적은 항목: 제목 …")
7. CLI `bin/office.mjs`는 그대로 둔다(사람용). 지침에서만 뺀다

## 3. 인터페이스

| 파일 | 내용 |
|---|---|
| `src/domain/meeting.mjs` | `GUIDE_VERSION = 3`, 지침 v3, `boardItems(text)` → `[{ title, folder, detail }]`(마지막 `### 칠판` 섹션), `normTitle(s)`, `syncPlan({ meetingId, items, todos, folders })` → `{ create: [{ title, folder, detail, key }], update: [{ id, patch }], remove: [id], skipped: [{ title, folder, reason }] }` (모두 순수) |
| `src/domain/daily-note.mjs` | 세션 줄에 `📁 이름` (`session.folder` 있을 때) |
| `src/usecases/todos.mjs` | `createTodo(raw, now, { source, meeting })` → 레코드에 `meeting: { id, key }` 저장 |
| `src/usecases/meeting.mjs` | `recentWork`/`refreshNote`가 세션에 `folder` 전달, `syncMeetingBoard(now)` → `{ meetingId, created, updated, removed, skipped }`, `getMeeting`에 `board: { meetingId, count, skipped }`, `endMeeting`이 아카이브 전에 동기화 |
| `src/http/server.mjs` | 3초 타이머(`MEETING_SYNC_EVERY`, config) |
| `public/js/views/meeting.js` | 상태 줄 |

`GET /api/meeting` 추가 필드: `board: { meetingId: string|null, count: number /* 이 회의가 칠판에 올린 살아 있는 항목 수 */, skipped: [{ title, folder, reason: 'unknown folder' | 'ambiguous folder' }] }`.

## 4. 테스트

1. 단위: `boardItems`(형식·하위 항목·마지막 섹션만·목록 없음·폴더 없는 줄), `syncPlan`(생성·중복 건너뜀·이 회의 항목 수정·빠진 open 항목 삭제·시작한 항목 유지·수동 체크/배정 항목 유지·폴더 못 찾음·같은 이름 둘), 지침 v3에 `### 칠판` 형식·CLI 문구 없음
2. 통합: 가짜 진행자 답변(`### 칠판` 3개) → 동기화 후 칠판 3개(`source: 'scrum'`) → 다음 답변에서 1개 빠지고 1개 세부 변경 → 삭제·수정 → 같은 답변 재동기화 no-op → 회의 끝 시 마지막 답변 반영 후 아카이브 → 수동 할 일과 같은 제목은 중복 안 됨 → 알 수 없는 폴더 `skipped`

## 5. 정한 기본값

1. 진행자의 제안은 확인 없이 칠판에 올라간다. 빼고 싶으면 칠판에서 지우거나 진행자에게 말한다
2. 목록에서 빠진 항목은 시작 전이고 손대지 않았을 때만 지운다
3. 7개 이하, 폴더를 못 찾으면 만들지 않고 회의실에 표시
