# Claude Office — 병렬 Claude 세션 관제 대시보드 설계

- 작성일: 2026-09-25
- 상태: 설계 승인됨, 구현 전
- 구현 위치: `~/claude-office` (독립 git 레포). 처음에는 실수로 다른 회사 레포 워크트리 안에서 만들었다가 2026-09-28 이 위치로 옮겼다(커밋 기록 유지).

## 1. 목적

Claude 데스크톱 앱(Code 탭)에서 작업 세션을 병렬로 돌릴 때(보통 3~5개, 최대 10개) 생기는 문제를 해결한다.

- 어떤 세션이 무엇을 하는지, 누가 내 응답을 기다리는지 한눈에 보이지 않는다.
- 리뷰가 병목이 된다.

목표 흐름은 이렇다. 앱에서 작업 지시 → 대시보드에서 상태 관제 → 리뷰 필요 항목이 보고서로 올라옴 → 보고서만 확인하고 컨펌. 필요하면 세션별 변경사항(diff)을 보고, 클릭 한 번으로 해당 채팅방으로 이동한다.

컨셉: 사용자는 팀 리드, 세션은 사원. 화면은 귀여운 픽셀 오피스.

## 2. 범위

| 단계 | 포함 |
|---|---|
| 1단계 (이 spec) | 관제, 보고, 로컬 컨펌, diff, 딥링크 |
| 2단계 (별도 spec) | 대시보드에서 작업 지시(세션 생성), 세션에 후속 메시지 전송, PR 머지/아카이브, 메뉴바 알림 |

1단계에서 뺀 것(YAGNI): 캐릭터 이동/걷기, 레벨·경험치, 커스텀 스킨, 층 분리(세션은 최대 10개).

## 3. 제약

- 로컬 전용이다. `127.0.0.1`에만 바인딩한다.
- 새 dependency는 0개다. Node 22 표준 라이브러리와 `git` CLI만 쓴다.
- 작업 세션을 절대 방해하지 않는다. hook이 실패해도 세션은 정상 진행되어야 한다.

| 항목 | 사실 | 근거 |

## 5. 아키텍처

접근안 비교 결과 **C (Hooks + 앱 파일)**를 채택했다.

| 안 | 요지 | 판정 |
|---|---|---|
| A. 앱 파일 폴링만 | 서버가 앱 JSON, 트랜스크립트, git을 폴링 | 탈락. `isRunning`이 없어 상태 정확도가 낮고 내부 포맷 전체에 의존한다 |
| B. 리드 Claude 세션 + MCP | `list_sessions`/`list_events`로 조회해 Artifact로 렌더링 | 탈락. 조회할 때마다 토큰을 쓰고 Claude 세션을 상시 켜둬야 한다 |
| **C. Hooks + 앱 파일** | 상태는 공식 hooks에서, 제목·딥링크만 앱 파일에서 | 채택 |

```
[작업 세션들] ──hooks──▶ ~/.claude/office/state/<cliSessionId>.json
[앱 세션 JSON] ─────────┐
[트랜스크립트 .jsonl] ───┼──▶ server.mjs (:7777) ──▶ public/index.html
[각 worktree git] ──────┘         └─▶ ~/.claude/office/confirmed.json
```

### 5.1 구성요소

| 파일 | 역할 |
|---|---|
| `hooks/report.mjs` | hook stdin JSON(`session_id`, `cwd`, `transcript_path`, `hook_event_name`, `message`)을 받아 `state/<session_id>.json`에 `{event, at, cwd, transcriptPath, message}`를 원자적으로 기록한다. 전체 try/catch, stdout 출력 없음, 항상 `exit 0` |
| `server.mjs` | `GET /api/sessions`, `GET /api/diff/:id`, `POST /api/confirm/:id`, `POST /api/summary/:id`, 정적 파일 서빙 |
| `public/index.html` | 픽셀 오피스, 칸반 결재함, 상세 패널. `/api/sessions`를 2초마다 폴링한다 |
| `install.mjs` (`--uninstall`) | `settings.json`을 백업한 뒤 hooks(`UserPromptSubmit`, `Notification`, `Stop`)를 병합하거나 제거한다. 여러 번 실행해도 결과가 같다 |
| `scripts/simulate.mjs` | fixture HOME에 가짜 세션 10개를 만들고 상태를 순환시킨다. 데모와 E2E에 쓴다 |

### 5.2 세션 병합 규칙

- 기준 키는 hook의 `session_id`다. 앱 JSON의 `cliSessionId`와 매칭한다.
- 매칭에 성공하면 `title`, `branch`, `sourceBranch`, `worktreePath`, `originCwd`, `prs`, 딥링크를 붙인다.
- 매칭에 실패하면 cwd 폴더명을 제목으로 쓰고 딥링크는 뺀다. 기능만 줄고 에러는 내지 않는다.
- hook 상태 파일이 없는 앱 세션(hooks 설치 전에 만든 세션)은 `lastActivityAt`이 24시간 이내일 때만 unknown으로 포함한다.
- 퇴근(목록에서 제외) 조건: 마지막 이벤트가 24시간보다 오래됐거나 `isArchived`가 true.
- 최근 활동 순으로 최대 10개만 표시한다.

### 5.3 상태 매핑

| 입력 | 상태 | 사원 모습 | 결재함 열 |
|---|---|---|---|
| 마지막 이벤트 `UserPromptSubmit` | working | 빠르게 타이핑, 모니터에 코드가 흐름 | 작업 중 |
| 마지막 이벤트 `Notification` | blocked | 땀방울, 빨간 "도와주세요" | 막힘 |
| 마지막 이벤트 `Stop` + 보고서 블록 있음 | review | 손 흔들며 "보고드려요", 서류를 듦 | 결재 대기 (태그: 보고서) |
| 마지막 이벤트 `Stop` + 보고서 블록 없음 | question | 머리 위 물음표 | 결재 대기 (태그: 질문) |
| 컨펌 시각이 마지막 이벤트보다 나중 | done | 커피잔에서 김 | 완료 |
| 상태 파일 없음 (5.2) | unknown | 회색, 말풍선 없음 | 표시 안 함 |

컨펌한 뒤 `UserPromptSubmit`이 들어오면, 그 이벤트가 컨펌보다 나중이므로 working으로 바뀐다.

`Notification`은 권한 요청뿐 아니라 입력 대기(idle, 약 60초)에도 발생한다. 그래서 hook은 기존 상태 파일의 `event`가 `Stop`이면 `Notification`을 무시하고 덮어쓰지 않는다. 턴이 끝난 뒤의 idle 알림이 review를 blocked로 바꾸지 않게 하기 위해서다. 작업 중(`UserPromptSubmit` 이후)에 발생한 `Notification`만 blocked로 처리한다.

## 6. 보고서

### 6.1 포맷

전역 `~/.claude/CLAUDE.md`에 아래 규칙을 추가한다(추가는 사용자가 직접 한다). "작업을 끝내고 사용자 확인이 필요할 때만 마지막 메시지를 이 포맷으로 마무리한다."

작성 규칙(2026-09-28 사용자 요청으로 변경): 모든 섹션은 번호 목록만 쓰고, 항목은 명사형(`~ 수정`, `~ 완료`, `~ 확인 필요`)으로 끝낸다. 세부 내용은 3칸 들여쓴 하위 번호 목록으로, 2단계까지. 원문은 `CLAUDE-report-rule.md`.

```markdown
## 결재 보고
### 한 줄 요약
1. <무엇을> <어떻게> 완료
### 리뷰 필요
1. `파일:라인` <무엇> 확인 필요
   1. <이유>
### 리스크 / 배포 의존성
1. <리스크, 없으면 "없음">
### 테스트 방법
1. <명령 또는 동작> 실행
   1. <기대 결과> 확인
```

### 6.2 3단 fallback

1. 트랜스크립트의 마지막 assistant 메시지에 `## 결재 보고` 블록이 있으면 `### ` 기준으로 섹션을 파싱한다.
2. 블록이 없으면 마지막 assistant 메시지의 앞부분 300자, diff 통계, PR 상태를 보여준다.
3. "요약 만들기" 버튼을 누를 때만 `claude -p --model haiku`로 요약을 만든다. 입력은 마지막 assistant 메시지와 diff 통계·변경 파일 목록이고, 출력은 6.1 포맷이다. timeout은 60초, 결과는 `~/.claude/office/summaries/<id>.md`에 캐시한다.

## 7. 화면

### 7.1 레이아웃

- 헤더: "오늘의 사무실", 카운터(출근 / 결재 대기 / 막힘), 소리 토글.
- 오피스: 5×2 책상 그리드. 빈 자리는 점선 의자로 표시한다. 화분과 창문(실제 시각에 따라 낮/밤)을 둔다.
- 결재함: 4열 칸반(작업 중 / 결재 대기 / 막힘 / 완료). 결재 대기 열은 보고서 카드를 위로 정렬한다.
- 상세 패널: 사원이나 카드를 클릭하면 오른쪽에서 열린다.
  - 헤더: 동물 · 제목, 브랜치 · PR 상태 · 턴 수
  - 탭: 보고서 | 변경사항 (+N −M, K files)
  - 보고서 탭은 마크다운 뷰어다(의존성 없는 자체 렌더러, HTML 이스케이프 후 변환): 제목, 굵게/기울임/취소선, `code`, 코드 블록, 표, 중첩 목록, 체크박스, 인용, 구분선, http(s) 링크. 보고서 아래에 "전체 응답 보기"(마지막 assistant 메시지 전체, 최대 20,000자)를 접어서 둔다. 보고서 블록이 없으면 마지막 응답 전체를 바로 보여준다.
  - 버튼: 채팅방 열기, PR 열기(PR이 있을 때만), 요약 만들기, 컨펌

### 7.2 캐릭터

- 동물 10종: 고양이, 강아지, 토끼, 곰, 펭귄, 여우, 햄스터, 판다, 오리, 개구리. `sessionId` 해시로 배정하므로 같은 세션은 항상 같은 동물이다.
- 명패는 세션 제목, 모니터 색은 레포(`originCwd`) 해시 색이다.
- 전부 CSS 픽셀아트로 그린다. 이미지 파일과 라이브러리는 쓰지 않는다.
- 라이트/다크 모드는 시스템 설정을 따른다.

### 7.3 알림

- 결재 대기 수가 늘면 탭 제목을 `(N) 결재 대기 · 오피스`로 바꾸고, 브라우저 Notification과 WebAudio "띵"을 낸다. 소리는 토글로 끌 수 있다.
- 컨펌하면 도장 "쾅" 애니메이션을 보여준다.

### 7.4 변경사항 탭

- `git -C <worktreePath> diff $(git merge-base <sourceBranch> HEAD)`로 커밋된 변경과 미커밋 변경을 함께 보여준다.
- untracked 파일은 `git status --porcelain`으로 목록만 보여준다.
- 파일별로 접고 펼칠 수 있다. 500KB를 넘으면 자르고 안내 문구를 띄운다.
- `worktreePath`가 없으면 "변경 추적 불가"로 표시한다.

## 7.5 컨펌 → 커밋·PR → 다음 작업 (2026-09-28 추가)

기존 앱 세션 입력창을 딥링크로 채우는 방법은 앱 코드에서 찾지 못했다. 새 세션을 만드는 `claude://code/new?q=<프롬프트>&folder=<경로>`는 입력창을 채우기만 하고 전송하지 않는다(사용자 확인, 2026-09-28).

| 버튼 | 서버 동작 | 사용자 동작 |
|---|---|---|
| 컨펌 · 커밋·PR | 컨펌을 기록하고, 지시문("커밋 → push → PR → 다음 작업 추천")을 `pbcopy`로 복사한 뒤 해당 채팅방을 연다 | ⌘V, Enter |
| OK · 1번 진행 / N번 진행 | 보고서의 `### 다음 작업` N번 항목으로 프롬프트(이전 세션 제목·브랜치·PR·한 줄 요약 + 할 일)를 만들고, `originCwd` 레포로 새 세션 입력창을 연다. 원래 세션은 완료 처리한다 | Enter |

- 링크와 폴더는 서버가 세션 데이터로만 만든다. 클라이언트는 세션 id와 항목 번호만 보낸다.
- `pbcopy`는 로케일이 비어 있으면 한글을 빈 문자열로 복사한다. 그래서 `LANG=en_US.UTF-8`을 명시한다.
- `OFFICE_DRY=1`이면 클립보드와 앱을 건드리지 않고 결과만 응답한다(테스트용).
- 이후 방향(3단계): 데스크톱 앱 없이 대시보드 웹에서만 작업하기. 대시보드가 세션을 직접 실행하고 대화하는 클라이언트가 되어야 하며, 이번 범위에서는 제외한다.

## 7.6 보류 · 아카이브 · 보관함 (2026-09-28 추가)

- 결재함 칸: 작업 중 / 결재 대기 / 보류 / 완료. 권한·입력 대기(blocked)는 사용자 조치가 필요하므로 결재 대기 칸에 빨간 "막힘" 태그로 둔다. 상단 카운터는 출근 / 결재 대기 / 보류.
- 세션마다 리드의 마지막 결정 하나(`confirm` | `hold` | `archive`)를 `~/.claude/office/decisions.json`에 저장한다. 결정 시각보다 새로운 hook 이벤트가 오면(다시 지시를 보내는 등) 결정은 자동으로 풀린다. 기존 `confirmed.json`은 confirm 결정으로 계속 읽는다.

| 버튼 | 동작 |
|---|---|
| 보류 / 보류 해제 | 보류 칸으로 이동, 외부 동작 없음. 보류 중인 세션은 24시간이 지나도 보드에 남는다 |
| 아카이브 | 사무실과 결재함에서 제거. 제목·한 줄 요약·마지막 활동 시각을 스냅샷으로 저장 |
| 보관함 (헤더) | 아카이브 목록: 작업 이름 · 날짜(마지막 활동) · 작업 한 줄 요약 · 복구 |
| 복구 | 보관함에서 빼고 보류 칸으로 이동 |
| 모두 아카이브 (완료 칸 헤더) | 완료 상태 세션을 한 번에 아카이브. 완료 카드가 있을 때만 보인다 |

## 8. 에러 처리와 보안

| 지점 | 처리 |
|---|---|
| hook | try/catch, 항상 exit 0, stdout 출력 없음, tmp 파일 → rename, node 기동 대비 오버헤드 10ms 이하 |
| 소스 병합 | 세션 단위, 소스 단위로 실패를 허용한다. 깨진 JSON은 건너뛴다 |
| git | 3초 timeout, 500KB에서 자름 |
| 바인딩 | `127.0.0.1:7777` |
| POST | `Origin`이 `http://127.0.0.1:7777`이나 `http://localhost:7777`이 아니면 403 |
| 딥링크 | `claude://` 스킴만 허용 |
| 요약 생성 | 클릭할 때만 실행, 60초 timeout, 실패하면 fallback 2를 유지 |
| install | `settings.json.bak-office-<ts>`로 백업, 반복 실행해도 결과 동일, uninstall은 우리가 추가한 항목만 제거 |
| 경로 주입 | `OFFICE_HOME`(기본 `~`), `OFFICE_APP_DIR`(기본은 앱 데이터 경로) 환경변수로 바꿀 수 있다. 테스트와 fixture 격리에 쓴다 |

## 9. 검증

### 9.1 테스트

`node --test`(내장 러너)로 돌린다. fixture는 앱 JSON, 트랜스크립트, 상태 파일, 임시 git 레포다.

- 보고서 파싱: 블록 있음 / 없음 / 섹션 누락
- 상태 판정: 5.3 표의 모든 행, 컨펌 해제
- 병합: 매칭 성공 / 매칭 실패 / 상태 파일 없음 / 앱 디렉터리 없음
- diff: merge-base, untracked 파일, worktree 없음, 크기 제한
- hook: 잘못된 stdin에서도 exit 0이고 stdout이 비어 있음. `Stop` 다음에 온 `Notification`은 무시
- install/uninstall: 두 번 실행해도 같은 결과, 기존 hooks 보존

### 9.2 메트릭

| # | 메트릭 | 기준 | 측정 |
|---|---|---|---|
| 1 | 상태 반영 지연 p95 | ≤ 3s | simulate 이벤트 발생 → UI 반영까지 |
| 2 | 상태 판정 정확도 | 100% | 10세션 × 5상태 시나리오 |
| 3 | hook 오버헤드 p95 (bare `node -e ''` 대비) | ≤ 10ms | 각 100회 실행. bare node 기동만 약 55ms라 절대값 기준은 측정 불가능해서 변경 |
| 4 | `/api/sessions` 응답 (10세션) p95 | ≤ 200ms | 반복 요청 |
| 5 | 결재 대기 → 채팅방 열기 | ≤ 2클릭 | 브라우저 자동화 |
| 6 | 앱 디렉터리 없이 기동 | 통과 | 빈 `OFFICE_APP_DIR`로 실행 |
| 7 | dependency 수 | 0 | `package.json` 확인 |
| 8 | 귀여움·가독성 | 루브릭 평균 ≥ 4/5 | 별도 judge 에이전트가 스크린샷을 채점. 최종 판단은 사용자 |

메트릭 8 루브릭(각 1~5점): 상태 구분 즉시성, 결재 대기의 눈에 띄는 정도, 캐릭터 매력, 정보 밀도 적정성, 다크모드 품질.

### 9.3 사용자 수동 확인 순서

1. `node install.mjs`로 hooks를 설치하고 `node server.mjs`를 실행한 뒤 `http://127.0.0.1:7777`을 연다.
2. 앱에서 새 세션 2개에 작업을 지시하고, 사원 2명이 타이핑하는지 확인한다.
3. 한 세션이 권한을 요청하게 만들고, 그 사원이 막힘 열로 옮겨지는지 확인한다.
4. 작업이 끝나면 결재 대기 카드를 클릭해 보고서와 변경사항을 본 뒤, 채팅방 열기와 컨펌을 눌러본다.
5. `node install.mjs --uninstall`을 실행하고 `settings.json`이 원래대로 돌아왔는지 확인한다.
