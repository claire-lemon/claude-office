# 할 일 칠판 · 회의실 제거 (2026-10-01)

## 목적

세션 관리(사무실·결재함·상세 패널·컨펌)에 집중한다. 쓰이지 않는 할 일 기능을 빼고, 세션 기록으로 만드는 업무일지만 남긴다.

## 조사 방법

1. 실제 사용 데이터(`~/.claude/office/todos.json`, `links.json`, `daily/`, `/api/sessions`)를 2026-10-01에 집계
2. 할 일 관련 코드 규모를 `wc -l`로 측정

## 사실

| 항목 | 값 |
|---|---|
| 만든 할 일 | 13개, 전부 회의 진행자가 만듦(`source: scrum`), 전부 2026-09-29 하루 |
| 직접 추가한 할 일 | 0개 |
| 지운 할 일 / 손으로 체크한 할 일 | 7개 / 2개 |
| 손으로 배정한 세션 (`assigned`) | 0번 |
| 세션 연결 스냅샷 (`links.json`) | 1건 |
| 결재함 세션 중 할 일에 연결된 세션 | 0 / 5 |
| 회의 (`## 회의 n`) | 2026-09-29 4번(개발 중 시험), 09-30·10-01 0번 |
| 2026-10-01 칠판 | 09-29 항목 4개가 끝나지 않은 채 남아 있음 |

할 일과 세션이 연결되는 길은 칠판의 **시작**과 손 배정뿐이었다. 일은 앱에서 바로 세션을 열어 시작했으므로 연결이 생기지 않았고, 연결이 없는 할 일은 끝나지 않아 다음 날로 넘어와 쌓였다. 할 일 역할은 결재 보고의 `### 다음 작업`과 **OK** 버튼(다음 작업으로 새 세션)이 세션 안에서 이미 맡고 있다.

## 결정

| 남김 | 뺌 |
|---|---|
| 업무일지: 오늘 일지의 자동 구간(어제 세션), AI 서술, 05시 타이머, `node bin/office.mjs narrate` | 오늘의 할 일 칠판, 시작·배정·다듬기, 결재함·패널의 📋/🏫 표시, 보관함의 지난 할 일 |
| 헤더 **📓 업무일지** 창 (`GET /api/journal`, `POST /api/narrate`) | 회의실·진행자·칠판 자동 반영, 회의실 문 |
| | `/api/todos`, `/api/todo-history`, `/api/start`, `/api/refine`, `/api/meeting*` |
| | 세션 응답의 `todoId`, `todoVia`, `meetingId` (화면만 쓰던 필드) |
| | 진행자 읽기 허용 규칙 (`node install.mjs`가 이제 지움) |

데이터 파일(`todos.json`, `links.json`, `daily/`, 진행자 지침 `CLAUDE.md`)은 지우지 않는다. 일지 자동 구간 안의 `## 칠판`·`## 할 일 기록`·`## 최근 프로젝트 폴더`는 그날 일지가 다시 채워질 때 빠지고, 마커 밖의 `## 회의 n`은 지난 일지에 그대로 남는다.

## 되살리기

1. 제거 커밋 하나를 되돌린다: `git revert <제거 커밋>`. 그 뒤 `node install.mjs`로 진행자 읽기 허용 규칙을 다시 넣는다.
2. 제거 직전 코드는 태그 `before-todo-removal`에 있다.
